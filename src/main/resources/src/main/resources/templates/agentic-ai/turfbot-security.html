ARCHITECTURE LESSON

Two OAuth identities, two responsibilities

Human browser sign-in

The public turfclub-web OIDC client uses Authorization Code with PKCE S256. The callback validates the ID token against the realm JWKS, issuer, audience and nonce.

Machine-to-machine API access

The svc-chatbot confidential service account gets a client-credentials access token with SVC_READ. The REST resource servers authenticate that token.

ARCHITECTURE LESSON

Preventing cross-role data access

A user restricted to accounting cannot request racing tools simply by asking Claude to do so. The model receives a filtered tool list, and the executor verifies every invocation against the allowed registry.

Audit and confidentiality

The uploaded implementation records questions, answers, tool invocations and model token costs in the MySQL chatbot schema with append-only safeguards. Sensitive data in model output still requires appropriate business governance.
